# Market-data, regulatory, and release gate

Release requires an accountable owner and evidence link for every applicable
item. “N/A” needs written rationale. A passing CI check is engineering evidence,
not legal approval, contractual permission, or proof of user validation.

## External blockers — automation cannot satisfy these

- [ ] The operating entity has a **signed licensed market-data vendor
  agreement** covering the exact NSE/EOD product uses, environments, territory,
  storage, derived data, display, alerts, paper trading, and disaster-recovery
  copies. Owner and restricted evidence link:
- [ ] Qualified India counsel has delivered a written
  **regulatory and privacy review** covering SEBI applicability, personalized
  analytics/alerts, research/adviser boundaries, beta/marketing claims, DPDP
  obligations, retention, subprocessors, cross-border processing, terms,
  consent, complaints, and incident notification. Owner and evidence link:
- [ ] Authorized staff have recruited, consented, and actually onboarded the
  approved real beta cohort under `docs/beta-playbook.md`. Owner and cohort
  evidence link:

No fixture, demo screen, automated test, checkbox generated by CI, or repository
document can close these blockers.

## Contract and legal evidence

- [ ] Signed vendor contract; product entity, territory, environments, user classes, and markets match launch.
- [ ] Rights confirmed for delayed/EOD display, storage duration, derived indicators, backtests, alerts, paper trading, caching, export, and any redistribution.
- [ ] Exchange entitlements, attribution, delay labels, usage reporting, audit rights, and per-user/device fees implemented.
- [ ] Vendor symbol master, corrections, corporate actions, calendars, rate limits, SLA/support, termination, and deletion obligations tested.
- [ ] No scraping, personal/free plan, or undocumented endpoint is used in production.
- [ ] Retention/lifecycle and disaster-recovery copies comply with contract.

## India regulatory, privacy, and product claims

- [ ] India counsel's advice has been converted into named product controls, disclosures, operating procedures, and launch restrictions, each with an owner.
- [ ] Launch jurisdictions and excluded territories are technically enforced.
- [ ] Execution is restricted to simulated funds or a contractually permitted
  broker sandbox. Production broker hosts/accounts, custody, deposits,
  withdrawals, live-money copy trading, and discretionary management are
  technically unreachable.
- [ ] Disclosures clearly state delayed data, source/as-of time, assumptions, uncertainty, fees/slippage, and that results are not guarantees.
- [ ] Marketing and testimonials are substantiated; no cherry-picked or guaranteed-return claims.
- [ ] Terms, privacy notice, consent, age eligibility, complaint path, and subprocessors are approved.

## Automated engineering evidence

Attach immutable CI run, commit, environment, and artifact identifiers. These
checks may be automated and must pass on the release candidate:

- [ ] Backend tests, frontend typecheck/build, JSON Schema/OpenAPI validation,
  FastAPI route-drift check, Compose validation, and migration smoke test pass.
- [ ] Cross-tenant path/header spoofing, role authorization, restricted DSL,
  prompt injection/fallback, stale or invalid data, next-session fill,
  idempotency, quota, and kill-switch checks pass.
- [ ] Acceptance records from `docs/runbooks.md` pass for backup restore,
  provider outage, data correction, duplicate replay, tenant isolation, prompt
  injection, and controlled rollback.
- [ ] Production secrets, encryption, audit retention, monitoring, paging, rate limits, quotas, and cost caps configured.
- [ ] Dataset, strategy, model, analysis, and paper-fill versions are reproducible.
- [ ] Security/privacy review has no unaccepted critical/high findings.
- [ ] Sandbox-host denylist, unknown-outcome reconciliation, partial-fill,
  stale-quote, delegated-authority, and all kill-switch tests pass.

## Human operational evidence

- [ ] Restore, outage, correction, incident, and rollback tabletop participants
  signed the resulting record; exceptions have owner and expiry.
- [ ] Product/data owner sampled source/as-of labels and analysis provenance.
- [ ] Support, privacy, vendor escalation, and incident contacts were called or
  otherwise verified through an approved test channel.
- [ ] Release approvers reviewed automated evidence rather than relying only on
  its pass/fail summary.

## Launch approval

Product, engineering, security/privacy, operations, data-licensing owner, and
India legal/compliance sign with date and release digest. Any later vendor,
market, jurisdiction, claim, distribution channel, data use, or execution change
reopens this gate.

Release is blocked while any external blocker is incomplete, even if every
automated check passes.
